El flujo completo del diagrama

LíneaQué significa
usuarios.id ── historial.id_usuarioFK: 1 usuario puede tener 0..n resultados. Las vistas de historial y ranking la usan para enlazar el nombre del jugador.
partidas.id ┄─ historial.id_partidaFK opcional (0..1): un resultado puede no tener tablero guardado. La rellena sp_crear_partida_completa.
Vistas → tablasLas 4 vistas son consultas guardadas: no guardan datos, en cada SELECT vuelven a calcular sobre las tablas.
Trigger → partidasSe ejecuta automáticamente en cada UPDATE de partidas y renueva actualizada_en (por eso la fila está resaltada).
Procedimientos → tablassp_registrar_partida inserta un resultado; sp_crear_partida_completa inserta historia + tablero en una operación atómica.
jugadores (discontinuo)Tabla del sistema antiguo: comparte base pero no tiene relación con ninguna de las demás.
⚠ Pendiente en PostgreSQL: a usuarios le faltan las 5 columnas de progreso (xp, victorias, derrotas, racha, puntaje_max). Se añaden con los ALTER ... ADD COLUMN IF NOT EXISTS ya presentes en schema-postgres.sql (líneas 24-28).
✔ Resumen: las vistas leen las tablas, el trigger reacciona a partidas y los procedimientos escriben. Todo convive en PostgreSQL 18.
